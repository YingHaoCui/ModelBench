# Four-arm KV experiment

Run `python kv_experiment.py <new-output-directory>` once. It writes deterministic
plain-text replay inputs and a manifest with three shuffled rounds of local-lb,
local-aware, pool-lb and pool-aware. No session affinity header is used. Reuse the
same input hashes for every arm. Tool/multimodal workloads intentionally exercise
fallback until their exact rendering profile is certified; do not use the default
coding-tool workload to claim KV-aware benefits.

For each arm/workload, configure its isolated Policy/Profile, capture required
manifest provenance, then use the existing runner:

```
python bench.py --base-url <policy-endpoint>/v1 --model <alias> --replay <directory>/high-repeat.jsonl --sessions 128 --turns 1 --concurrency 16 --seed 23 --output <arm-round-workload-output>
```

Set credentials through the supported API-key environment variable. Use turns=4
for multi-turn. Record cold starts and warmup separately; never compare one warm
arm against another cold arm. Save requests.jsonl, summary and runtime/Router/pool
metrics. The fixed assistant history is synthetic and identical across arms.
Prefix probability is a request-generation parameter, not a measured token hit rate.

Use `compare()` on corresponding summaries as an initial pair check: high-repeat
TTFT P95 improvement >=10%; low-repeat P95 regression <=5% and throughput loss <=5%;
no increase in error rate. It refuses fewer than 100 successful observations and
never interprets cache hit ratio as performance evidence. A pair pass is not overall
acceptance. Inspect P50/P95/P99, sample uncertainty, three rounds, queueing, connector
bytes, correctness, normal query P95 <=20 ms and unavailable query P99 <=55 ms.

Repeat while adding P3/D3, removing P1/D1 after in-flight completion, restarting
controller/conductor/MetaService separately, and losing a storage provider. Record
timestamps as external events; this tool does not automate destructive cluster
actions. Test two or more Router replicas for cache-driven herding. Aggregated
Weighted can be used for gradual rollout; P/D requires separate experiment Policy
or ingress groups. Do not report existing P/D Weighted support.
